description: 변경 내용을 빌드 검증 후 커밋·푸시하여 GitHub Pages에 자동 배포한다
---

현재 변경 내용을 GitHub Pages(https://kgh0415.github.io/Hub/)에 배포한다.
main 브랜치에 push하면 GitHub Actions가 자동으로 빌드·배포한다.

수행 순서:
1. `git status`로 변경 내용을 파악한다. 변경이 없으면 그 사실을 알리고 중단한다.
2. `npm run build`를 실행해 빌드가 성공하는지 먼저 확인한다.
   - 빌드가 실패하면 push하지 말고, 실패 원인(에러 메시지)을 사용자에게 보고한 뒤 중단한다.
   - (빌드가 실패한 채 push하면 Actions에서도 실패하므로 반드시 선검증한다.)
3. 빌드가 성공하면 변경 내용을 요약하는 간결한 한글 커밋 메시지를 작성한다.
   - 사용자가 $ARGUMENTS 로 메시지를 지정하면 그것을 우선한다.
   - `Co-Authored-By` 등 서명은 넣지 않는다.
4. `git add -A` 후 커밋한다.
5. `git push origin main` 으로 푸시한다. (푸시가 곧 배포 트리거다.)
6. 결과를 짧게 보고한다:
   - 커밋 해시, 푸시 결과
   - "GitHub Actions가 자동 빌드·배포 중. 1~2분 뒤 https://kgh0415.github.io/Hub/ 에서 Ctrl+Shift+R 로 확인" 안내
   - Actions 탭에서 실행이 초록불인지 확인하라는 안내

주의:
- 훅(hook)이나 서명을 건너뛰는 플래그(`--no-verify` 등)는 사용하지 않는다.
- 요청받지 않은 파일·구조는 바꾸지 않는다.
